OPEN REPOSITORIES / PEOPLE + AGENTS

分享一招，不必注册本站。

带一个公开仓库，写一份 Markdown，或让你的 Agent 帮忙。
通过 GitHub PR 投稿，个人上下文由你自己管理。

浏览、取用、生成文件均免站内登录。向GitHub写入需要GitHub身份或获授权凭据。公共PR本身可见，提交前请确认选定内容允许公开。
投稿文件在本机生成；点击GitHub链接后由你确认提交。公共PR可见，提交前确认内容允许公开。

收录一个公开仓库

Skill需核验公开来源、路径与版本；网页不抓取仓库；PR构建检查来源。

把这段任务交给你的 Agent

人和Agent遵循同一份贡献规范。Agent使用用户已授权的GitHub身份，不需要本站账号。

下载贡献规范
Agent先读取贡献规范，只处理用户选定且允许公开的方法；使用用户授权的GitHub身份发起PR。


提交以后，发生什么
PR提交 → 自动检查 → 首次作者简短审核 / 可信作者快速通道 → 合并与构建 → 站点收录。
提交、收录、精选是不同状态。自动检查通过不代表已验证有效；首次作者审核建议一个工作日内响应，可信投稿目标检查通过后十分钟内可见，均为待验证目标。
打开公共仓库：下载文件 → 登录GitHub → 打开公共内容仓库 → 在指定目录上传文件并发起PR → 通过PR链接跟踪检查与收录。没有自己的仓库也可通过GitHub贡献。

为什么叫上下文银行
延续小队讨论的概念，也能容纳经验与工作流。副标题始终说明“Skills · 经验 · 工作流”，避免被理解为托管个人聊天记录。
命名为建议；尚未调查商标与域名。参考 skills.sh 的目录发现路径，本站使用原创界面与通用方法，产物示例采用合成内容。
同事之间怎么传播
从一条能马上照做的实践链接开始：一句痛点＋一个脱敏样例＋使用步骤。教练带一次任务，同事独立复用；人或Agent用PR更新方法，合并构建后生成可分享详情页。
初始方法尚未经过平台实测认证；我们按内容完整度编辑推荐，不展示虚构使用量。
